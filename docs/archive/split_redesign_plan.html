3. Target design (as decided)

Config keeps exactly two flat class pools of any length: CLEAN_IMAGE_FOLDERS = all folders without moire, MOIRE_IMAGE_FOLDERS = all folders with moire. The split engine derives units automatically:

  • Twin units - a clean and a moire folder whose image filename sets are identical are auto-recognized as scene-twin folders (LCDMoire gt/moire). Each filename-matched (moire, clean) file pair stays one indivisible unit of 2 samples, so twins never leak across splits (guarantee unchanged).
  • Folder units - every other folder (AirDroid) is one indivisible unit holding all its images with its class label, so the roughly 4-6 near-duplicate photos of one object never span two splits.
  • Loud failures - missing or empty folder, partial filename overlap between a clean and a moire folder (suspicious near-twins), or an ambiguous binding (one folder matching two opposite-class folders) raise ValueError. Unequal list lengths are no longer an error.
CLEAN_IMAGE_FOLDERS (65 folders) + MOIRE_IMAGE_FOLDERS (104 folders)
↓
detect twin folder pairs by identical filename sets (LCDMoire train/test gt and moire)
↓
split units = 3160 twin units (1 moire + 1 clean each) + 63 clean folder units (423 imgs) + 102 moire folder units (385 imgs) = 3325 units / 7128 samples
↓
random.Random(seed).shuffle(units), then cuts over unit counts: train = round(N x 0.8), val = round(N x 0.1), test = remainder

7. Known limitations (accepted)

  • The same physical object can appear clean in one split and moire in another (e.g. battery vs flat battery), because the flat class pools carry no object mapping. This slightly inflates test metrics; documented in docs/dataset.md.
  • Class balance per split is approximate rather than exact.
